# IT Hub

ศูนย์รวมบริการ IT ของโรงงาน — สแกน QR บนอุปกรณ์เพื่อดูข้อมูลและแจ้งซ่อม, ยื่นคำขอบริการ IT ทุกประเภท
ผู้ใช้ทั่วไปไม่ต้อง login มีเฉพาะเจ้าหน้าที่ IT (Admin) ที่ต้อง login

- หน้าผู้ใช้: `https://abms.ddns.net:8445/it-hub/`
- QR อุปกรณ์: `https://abms.ddns.net:8445/it-hub/a/<รหัสอุปกรณ์>`
- หน้า Admin: `https://abms.ddns.net:8445/it-hub/admin`

## Import ทะเบียนอุปกรณ์จาก Excel

หน้า Admin → **ทะเบียนอุปกรณ์ → Import Excel** เลือก `.xlsx` รูปแบบ FM-IT-001 แล้วกด **ตรวจสอบไฟล์** เพื่อดูรายการเพิ่มใหม่/แก้ไข/ตรงเดิมและรายละเอียดก่อน–หลัง จากนั้นกด **ยืนยัน Import** ดาวน์โหลดแบบฟอร์มเปล่าที่มี Sheet `FM-IT-001 (ATS)` และ `FM-IT-001 (INNO)` ได้ในหน้าต่างเดียวกัน แบบฟอร์มไม่มีข้อมูลพนักงานจริง

คอลัมน์ A–J: ลำดับ, หมายเลข, ผู้ครอบครอง, ยี่ห้อ/รุ่น, Serial No, หน่วยงานที่ใช้, วันที่ขึ้นทะเบียน, หมายเหตุ (ชื่อเล่น), Type, หมายเหตุเพิ่มเติม โดย Type ใช้ `Notebook`, `Computer`, `AIO` และต่อท้ายชื่อเครื่องได้ เช่น `Notebook/ATSIT01` รองรับวันที่ Excel / `วว/ดด/ปปปป` / `YYYY-MM-DD` ทั้ง ค.ศ. และ พ.ศ. อ่านแถวที่ซ่อนหรืออยู่นอก autofilter ด้วย รับได้ไม่เกิน 1,000 รายการและไฟล์ 5 MB ต้องแปลงสูตรเป็นค่าข้อมูลก่อนนำเข้า

ระบบจับคู่ด้วย Serial เพื่อรักษา asset ID และประวัติซ่อม แม้เปลี่ยนรหัสทะเบียน เครื่องไม่มี Serial ใช้รหัสเดิม หรือรุ่น+ผู้ครอบครอง+หน่วยงานที่ตรงกันเพียงรายการเดียว รหัสซ้ำ/Serial ซ้ำ/การใช้รหัสของคนละเครื่องที่ยังไม่ได้ย้ายออกจะบล็อกทั้งไฟล์ ช่องว่างคงข้อมูลเดิมไว้ ไม่ลบอุปกรณ์ที่ไม่มีในไฟล์ และคงสถานะ/สถานที่/ประกัน/สเปกเดิมไว้ หากข้อมูลเปลี่ยนหลังตรวจสอบจะต้องตรวจไฟล์ใหม่ การบันทึกทั้งไฟล์เป็น transaction เดียว นำเข้าซ้ำไม่เพิ่มเครื่องซ้ำ

รายการเปลี่ยนรหัสต้องพิมพ์ QR ใหม่ มีปุ่มพิมพ์เฉพาะรายการเหล่านี้หลัง Import สำเร็จ การ Import นี้อัปเดตทะเบียนอุปกรณ์โดยตรง ไม่แก้ snapshot เอกสาร FM-IT-001 ที่เคยบันทึกหรือส่งลงนามแล้ว ไฟล์อัปโหลดอ่านจาก PHP temporary upload และไม่เผยแพร่หรือเก็บในเว็บ

API สำหรับ Admin เท่านั้น: `POST /admin/assets/import/preview`, `POST /admin/assets/import/apply` (multipart `file`, และ `preview_hash` จากขั้นตรวจสอบสำหรับ Apply), `GET /admin/assets/import/template` คำขอ POST ต้องมี `X-IT-Hub: 1` ตามกติกาเดิม ต้องมี PHP ZipArchive และ SimpleXML ไม่ต้องเพิ่ม migration หรือ package

ทดสอบด้วย `php api/tests/asset_import.php` (temporary tables; ไม่แก้ทะเบียน/ใบงานจริง)

## ติดตั้ง (ครั้งแรก)

**1. ฐานข้อมูล** — ใน phpMyAdmin ด้วย root (แท็บ SQL) รันตามลำดับ:

1. `sql/00_create_db.sql` — สร้าง `ithub` + ให้สิทธิ์ `atthasan`
2. เลือก database `ithub` แล้วรัน `sql/01_schema.sql`
3. `sql/02_seed_assets.sql` — นำเข้าอุปกรณ์ 59 เครื่องจาก FM-IT-001
4. `sql/03_employees_approvals.sql` — เพิ่มทะเบียนพนักงานและการลงนามอนุมัติ (ระบบเดิมรัน migration ที่ยังไม่ได้ใช้ตามลำดับ)
5. `sql/04_requester_signatures.sql` — เพิ่มตารางเก็บชื่อและลายเซ็นผู้ร้องขอ (คำขอเดิมไม่เปลี่ยน)
6. `sql/05_completion_approvals.sql` — เพิ่มขั้นตอน ผอ./ผจก. รับรองผลก่อนปิดงานและเก็บหลักฐานแต่ละรอบ (รันครั้งเดียว)
7. `sql/06_it_staff_signatures.sql` — เพิ่มลายเซ็นบัญชีผู้ดูแลและประวัติลายเซ็นเจ้าหน้าที่ IT ในใบงาน (รันครั้งเดียว)
8. `sql/07_it_documents.sql` — เพิ่มเอกสารฝ่าย IT การลงนามตามตำแหน่งและประวัติเอกสาร (เพิ่มตารางใหม่ ไม่แก้ใบงานเดิม)
9. `sql/08_purchase_signatures.sql` — เพิ่มลายเซ็นผู้รับเรื่องของ Admin และลายเซ็นจัดซื้ออีก 3 ตำแหน่งที่ลงนามต่อหลังปิดงานได้
10. `sql/09_borrow_approval.sql` — เก็บผลอนุมัติเบิก–ยืมของ Admin IT Hub และเชื่อมบันทึก FM-IT-008 ที่สร้างหลังอนุมัติ
11. `sql/10_ticket_archives.sql` — คิวสร้าง PDF และส่งเอกสารปิดงานไป NAS พร้อมผลการส่งและ snapshot แต่ละฉบับ
12. `sql/11_archive_folders.sql` — เก็บพาธไฟล์ในโฟลเดอร์แยกตามแบบฟอร์มบน NAS

ติดตั้งตัวส่งอีเมลด้วย `composer install --no-dev --working-dir=api` และตั้งค่า `smtp` / `employee_source` ใน `api/config.php` ตาม `api/config.example.php`; ห้ามเก็บรหัสผ่านใน Git

**2. สร้าง Admin คนแรก**

```bash
php /var/www/IT-Hub/api/bin/create-admin.php <username> "<ชื่อที่แสดง>"
```

**3. Apache** (ต้องใช้ sudo) — เพิ่มบรรทัดนี้ใน `/etc/apache2/sites-available/web-erp-ssl.conf`
ทั้งใน `<VirtualHost *:8443>` และ `<VirtualHost *:8445>` วางก่อนบรรทัด `DocumentRoot /var/www/web-erp/public`
(API รันผ่าน PHP-FPM pool `www` แยกจาก pool `erp-production` ของ ERP)

```apache
Include /var/www/IT-Hub/deploy/apache-it-hub.conf
```

```bash
sudo apache2ctl configtest && sudo systemctl reload apache2
```

## ความปลอดภัย

- หน้าสแกน QR แสดงเฉพาะ รหัส/รุ่น/หน่วยงาน/ชื่อเล่น — ไม่แสดง Serial, ชื่อจริง, หมายเหตุภายใน
- หน้าติดตามสถานะไม่แสดงข้อมูลผู้แจ้ง และไม่แสดงบันทึกที่ตั้งเป็น "ภายใน"
- จำกัดการส่งคำขอ 10 ครั้ง / 10 นาที / IP, login ผิด 5 ครั้งล็อก 15 นาที
- คำขอที่เปลี่ยนข้อมูลต้องมี header `X-IT-Hub` + cookie `SameSite=Strict` (กัน CSRF)
- ห้ามใส่รหัสผ่านชั่วคราวของ E-mail ในช่องผลการดำเนินการ (ผู้แจ้งเห็นได้)

## พนักงานและการลงนาม FM-IT-010

- หน้า Admin → ข้อมูลพนักงาน (`/admin/employees`) เพิ่ม/แก้ไข/ปิดใช้งานพนักงานและกำหนดสิทธิ์ผู้อนุมัติได้
- ปุ่ม “ดึงข้อมูล E-Procurement” อ่านข้อมูลต้นทางอย่างเดียว แยกรายการตาม user + company; อัปเดตข้อมูลติดต่อ/องค์กร/สถานะ และปิดรายการต้นทางที่หายไป โดยไม่ลบประวัติหรือพนักงานที่เพิ่มเอง
- หน้าพนักงานและตัวเลือกผู้อนุมัติรวม user ต้นทางคนเดียวกันที่ชื่อ อีเมล โทรศัพท์ แผนก ตำแหน่ง สถานะและสิทธิ์ตรงกันเป็นรายการเดียว พร้อมชื่อบริษัททั้งหมด; กรองด้วยบริษัทใดก็พบรายการรวมได้ การแก้ไขรายการรวมอัปเดตข้อมูลร่วมกันทุกบริษัท โดยคงบริษัทและ ID ที่ประวัติลงนามอ้างอิงไว้
- การนำเข้าครั้งแรกให้สิทธิ์ผู้อนุมัติจากหัวหน้าแผนกที่กำหนดในต้นทาง หรือรายชื่อใน workflow PR/PO ที่เปิดใช้ หลังจากนั้นคงสิทธิ์ที่ Admin ตั้งใน IT Hub ไว้
- ผู้ยื่น FM-IT-010 ต้องเลือกผู้อนุมัติที่เปิดใช้งานและมีอีเมล ระบบบันทึกคำขอและส่งอีเมลขอลงนามทันที หาก SMTP ล้มเหลวยังคงเก็บเลขที่คำขอ พร้อมแสดงให้ติดต่อ IT
- ผู้ยื่น FM-IT-010 วาดลายเซ็นผู้ร้องขอก่อนส่ง ระบบเก็บภาพ PNG พร้อมชื่อและวันเวลาจากเซิร์ฟเวอร์ใน transaction เดียวกับคำขอ แสดงในหน้า Admin และช่องลงนามผู้ร้องขอของฉบับพิมพ์; ไม่เผยลายเซ็นใน tracker สาธารณะและไม่จำลายเซ็นในเครื่อง คำขอเดิมที่ไม่มีลายเซ็นแสดงชื่อผู้ร้องขอพร้อมช่องเซ็นว่าง
- ผู้อนุมัติเปิดลิงก์ ตรวจรายละเอียด เลือกใช้ลายเซ็นที่เก็บใน E-Procurement หรือวาดใหม่ แล้วยืนยันอนุมัติ/ไม่อนุมัติ (ปฏิเสธต้องมีเหตุผล) การเปิดลิงก์หรือมีลายเซ็นต้นทางอย่างเดียวไม่เปลี่ยนสถานะ
- ลายเซ็นเดิมอ่านจาก E-Procurement โดยตรง ไม่ต้อง sync ใหม่ จับคู่ด้วย source user ID + company membership + อีเมลผู้อนุมัติ โดยต้องเปิดใช้งานทั้งสองระบบ แสดงภาพเฉพาะผู้ถือ token ที่ยังใช้ได้; ไม่มีภาพใน public dropdown/tracker หากไม่มีลายเซ็นหรืออ่านต้นทางไม่ได้ยังวาดใหม่ได้
- เมื่อใช้ลายเซ็นเดิม ระบบตรวจ hash ว่ายังตรงกับภาพที่เห็นแล้วเก็บสำเนาในใบคำขอพร้อมบันทึกที่มาภายใน การแก้/ลบภาพต้นทางภายหลังไม่เปลี่ยนหลักฐานของใบที่ลงนามแล้ว ไม่เติมลายเซ็นย้อนหลังให้ใบที่ยังไม่ได้ยืนยัน
- ลิงก์อายุ 7 วัน ลงนามได้ครั้งเดียว ใช้ token สุ่ม 256 บิต โดยเก็บเฉพาะ hash ในฐานข้อมูล และรับ token ผ่าน POST body; URL ใช้ fragment เพื่อไม่ส่ง token ไปยัง access log
- Admin ส่งอีเมลใหม่หรือเลือกผู้อนุมัติใหม่ระหว่างรอลงนามได้ (เว้นอย่างน้อย 1 นาที) ลิงก์เดิมจะใช้ไม่ได้; ผู้อนุมัติที่ปิดใช้งาน/ถูกถอนสิทธิ์/เปลี่ยนอีเมลต้องแก้ผู้รับก่อนส่งใหม่
- IT เริ่มงานของคำขอที่มีขั้นตอนอนุมัติได้หลังหัวหน้าฝ่ายลงนามอนุมัติเท่านั้น การไม่อนุมัติในขั้นหัวหน้าฝ่ายจะปิดคำขอเป็น “ไม่อนุมัติ” และคำขอที่ยกเลิกแล้วลงนามไม่ได้
- ก่อนปิด FM-IT-010 ที่มีขั้นหัวหน้าฝ่ายเป็น “เสร็จสิ้น” ต้องกรอกผลดำเนินการและขอลายเซ็น ผอ./ผจก. เพิ่มในหน้า Admin ของใบนั้น เลือกผู้รับรองจาก dropdown (ค่าเริ่มต้น “สมไชย อักษร”; ตั้งชื่อเริ่มต้นได้ใน `completion_default_approver_name`) แล้วกด “บันทึกผลและขอลายเซ็น ผอ./ผจก.” ระบบส่งอีเมลพร้อมผลที่ขอรับรอง
- ผอ./ผจก. ใช้ลายเซ็น E-Procurement หรือวาดใหม่และยืนยันผ่านลิงก์ เมื่อรับรองแล้ว IT กด “ตรวจสถานะลายเซ็น” และ “ปิดงานเป็นเสร็จสิ้น” ได้ การยืนยันของ ผอ./ผจก. ไม่ปิดงานเอง; ไม่รับรองผลต้องระบุเหตุผล โดยยังคงงานเปิดให้ IT แก้ไขและส่งใหม่
- แก้ผลดำเนินการที่บันทึกไว้หรือเปิดงานที่ปิดแล้วขึ้นใหม่ต้องขอรับรองอีกรอบ ใช้ work revision และ snapshot ผลเพื่อกันลิงก์/ลายเซ็นรอบเก่า และเก็บภาพกับผลพิจารณาเดิมไว้แยก attempt; ส่งซ้ำระหว่าง pending ใช้กฎ 1 นาทีและยกเลิกลิงก์เก่าเหมือนขั้นหัวหน้าฝ่าย
- เก็บชื่อและอีเมลผู้อนุมัติ ณ เวลาส่ง พร้อมลายเซ็น วันเวลา IP และหมายเหตุเมื่อยืนยัน; การแก้รายชื่อพนักงานภายหลังไม่เปลี่ยนหลักฐานที่ลงนามแล้ว
- หน้าติดตามสาธารณะแสดงเฉพาะสถานะและความคืบหน้า; ลายเซ็นและข้อมูลติดต่ออยู่ในหน้า Admin / ฉบับพิมพ์ ซึ่งมีช่องลงนามครบ 5 ตำแหน่งตาม Rev.01 การลงนามผ่านอีเมลใช้กับหัวหน้าฝ่าย / ผู้อนุมัติและ ผอ./ผจก. รับรองผล
- หน้า Admin → ผู้ดูแลระบบ → คอลัมน์ “ลายเซ็น” วาดหรืออัปโหลด PNG/JPG/WebP ได้ (ไฟล์ไม่เกิน 8 MB แปลงเป็น PNG ก่อนบันทึก) ชื่อที่แสดงของบัญชีเป็นชื่อเจ้าหน้าที่ในเอกสาร ลายเซ็นประจำบัญชีแก้หรือลบได้โดยผู้ดูแลเหมือนการจัดการบัญชีอื่นๆ
- เมื่อผู้ดูแลที่มีลายเซ็นส่งผลขอรับรองจาก ผอ./ผจก. หรือปิดงานที่มีผลดำเนินการ ระบบเก็บสำเนาชื่อ/ภาพ/วันเวลา/IP ของผู้กดจริงไว้กับ revision ของผล ไม่ยืมลายเซ็นจากบัญชีผู้รับผิดชอบคนอื่น ถ้ามีผู้ลงนามไว้แล้วจะคงคนเดิมของรอบนั้น
- ใบงานที่มีผลดำเนินการแล้วและยังไม่มีภาพเจ้าหน้าที่ มีปุ่ม “ลงนามเจ้าหน้าที่ IT ด้วยลายเซ็นของฉัน” สำหรับบันทึกลงใบปัจจุบันได้ รวมถึงงานเสร็จแล้วที่มีผลดำเนินการ โดยยังต้องผ่านอนุมัติหัวหน้าฝ่ายถ้าใบนั้นมีขั้นตอนนี้ ไม่ลงนามใบที่ปฏิเสธ/ยกเลิก
- ฉบับพิมพ์นำภาพกับชื่อไปใส่ช่อง “เจ้าหน้าที่เทคโนโลยีสารสนเทศ” โดยตรง การเปลี่ยน/ลบภาพประจำบัญชีไม่เปลี่ยนใบที่ลงนามแล้ว; เปลี่ยนผลที่บันทึกหรือเปิดงานใหม่จะไม่แสดงภาพรอบเก่าปนผลใหม่ ไม่มีภาพใน tracker สาธารณะและไม่มีการลงนามย้อนหลังอัตโนมัติ
- คำขอเดิมที่ไม่มีรายการอนุมัติยังใช้ขั้นตอนเดิม ใบขอซื้อใหม่ใช้การลงนามต้นสังกัดตามหัวข้อ FM-IT-007 ด้านล่าง
- ข้อมูลอุปกรณ์และสถานที่จาก QR ผูกเฉพาะใบแจ้งซ่อม คำขอบริการ/อีเมล/ยืม/จัดซื้อไม่แนบข้อมูลนี้ แม้เปิดจาก URL เก่าที่มี `?asset=`; คำขอเดิมที่ไม่ใช่แจ้งซ่อมจะไม่แสดงข้อมูลอุปกรณ์ในรายละเอียด ฉบับพิมพ์ หน้าอนุมัติ หรือประวัติของอุปกรณ์

ตรวจการทำงานด้วย `php api/tests/approval_integration.php` (ต้องมี Python 3, PHP GD และสิทธิ์สร้าง temporary table) การทดสอบใช้ตารางชั่วคราวเฉพาะ connection และ SMTP จำลองบน loopback จึงไม่แก้ข้อมูลจริงหรือส่งอีเมลออก

ตรวจขั้นตอนก่อนปิดงานเพิ่มเติมด้วย `php api/tests/completion_workflow.php` และการรวมพนักงานด้วย `php api/tests/employee_grouping.php`

ตรวจลายเซ็นเจ้าหน้าที่ด้วย `php api/tests/it_staff_signatures.php` (ใช้ temporary tables ไม่ส่งอีเมล)

## ใบขอซื้อ FM-IT-007

หน้าสาธารณะ `/request/purchase` ให้ผู้ขอวาดลายเซ็นและเลือก **ผู้มีอำนาจอนุมัติต้นสังกัด (หน./ผจก.)** จาก dropdown ก่อนส่ง ระบบเก็บลายเซ็นผู้ขอพร้อมชื่อ/เวลาจากเซิร์ฟเวอร์ และส่งอีเมลไปยังผู้ที่เลือกโดยใช้ช่องทางเดียวกับ FM-IT-010 ผู้อนุมัติอ่านวัตถุประสงค์ รายการอุปกรณ์ ความเร่งด่วน วันที่ต้องการ และสเปกได้จากอีเมลและหน้าลงนาม เลือกภาพ E-Procurement หรือวาดใหม่แล้วกดยืนยัน

IT รับเรื่อง/เริ่มงาน/ปิดงานของใบใหม่ได้หลังต้นสังกัดอนุมัติ ปฏิเสธต้องระบุเหตุผลและคำขอเปลี่ยนเป็นไม่อนุมัติ หากส่งอีเมลไม่สำเร็จยังคงเก็บคำขอและภาพผู้ขอไว้ โดย Admin ส่งอีเมลใหม่หรือเปลี่ยนผู้รับระหว่างรอลงนามได้ตามกฎเดิม การส่งลิงก์หรือเปิดลิงก์ไม่ถือว่าลงนาม

ช่อง **ผู้รับเรื่อง (ฝ่ายเทคโนโลยีสารสนเทศ)** ใช้ลายเซ็นประจำบัญชี Admin ที่กดรับเรื่อง/เริ่มดำเนินการจริง เก็บภาพ ชื่อ และเวลาเป็นสำเนา ไม่ใช้ชื่อผู้รับผิดชอบแทนผู้ลงนาม กด **ลงนามผู้รับเรื่องด้วยลายเซ็นของฉัน** ได้ทันทีหลังต้นสังกัดอนุมัติ ไม่ต้องกรอกผลดำเนินการก่อน ใบที่รับเรื่องไว้แล้วหรือปิดแล้วก็กดบันทึกลายเซ็นได้เมื่อยังไม่มีผู้รับเรื่องลงนาม การเปลี่ยนรูปประจำบัญชีหรือแก้ผลภายหลังไม่เปลี่ยนลายเซ็นผู้รับเรื่องเดิม

ส่วน **ข้อมูลจัดซื้อและลายเซ็นเพิ่มเติม FM-IT-007** ให้ IT กรอกผู้ขาย ใบเสนอราคา ราคา/VAT และเลือกผู้รับอีเมลจาก dropdown แยก 3 ตำแหน่ง: ผอ./ผจก. ฝ่ายสนับสนุนและติดตั้ง, ผู้ตรวจสอบ (ผจก.ฝ่ายจัดซื้อ), ผู้ช่วยกรรมการผู้จัดการ แล้วกดส่งขอลายเซ็นทีละตำแหน่ง การส่งจะบันทึกข้อมูลจัดซื้อและผลที่กำลังกรอกไว้ด้วย

**ใบขอซื้อปิดงานได้โดยไม่ต้องรอ 3 ลายเซ็นนี้ครบ** และยังส่ง/ส่งใหม่/ลงนามเอกสารต่อหลังสถานะเสร็จสิ้นได้ การรับรองหรือไม่รับรองใน 3 ตำแหน่งไม่เปลี่ยนสถานะงาน ไม่รับรองต้องมีเหตุผล ข้อมูลที่ส่งลงนามผูกกับคำขอ/ข้อมูลจัดซื้อ/ผลและรุ่นของข้อมูล หากแก้ไขข้อมูลหรือเปิดงานใหม่ต้องขอลงนามสำหรับฉบับใหม่ ภาพฉบับก่อนเก็บไว้แต่ไม่พิมพ์ปนกับข้อมูลที่แก้ไข ใบร้องขอ IT (FM-IT-010) ยังคงบังคับลายเซ็นรับรองผลก่อนปิดงานตามเดิม

ปุ่ม **พิมพ์ฟอร์ม** ในหน้าใบขอซื้อพิมพ์ FM-IT-007 Rev.02 โดยตรง เป็น A4 แนวตั้ง พร้อมข้อมูลผู้ขอ/สเปก/จัดซื้อ และภาพที่ยืนยันแล้วตรงทั้ง 6 ช่อง ช่องที่ยังไม่มีหลักฐานเว้นว่าง ข้อมูลสั้นรวมถึงสเปกว่างพิมพ์ได้หน้าเดียว ข้อความยาวต่อหน้าได้ครบ ใบเก่ายังพิมพ์ได้โดยไม่เติมภาพย้อนหลัง ไม่สร้างเอกสารใหม่ซ้ำในทะเบียนเอกสาร และไม่เดาจำนวนอุปกรณ์ที่ผู้ขอไม่ได้ระบุ

ทดสอบด้วย `php api/tests/purchase_approval.php` (temporary tables + SMTP จำลอง ไม่ส่งอีเมลจริง)

ทดสอบผู้รับเรื่องและการลงนามทั้ง 3 ตำแหน่งหลังปิดงานด้วย `php api/tests/purchase_signoffs.php` (temporary tables + SMTP จำลอง)

## เอกสารฝ่าย IT (FM-IT-001–011)

เมนู **เอกสารฝ่าย IT** (`/admin/documents`) รองรับ 12 แบบ รวม FM-IT-007.1 แบบ INNO โดยอ้างอิง Excel/PDF ใน `FM-IT/` ดาวน์โหลด Excel ต้นฉบับได้เฉพาะผู้ดูแล ไฟล์ต้นฉบับมีข้อมูลภายในและถูกละเว้นจาก Git

ปุ่ม **พิมพ์แบบฟอร์มเปล่า** ในแต่ละแบบเปิดหน้าต่างพิมพ์ได้ทันที พร้อมช่องว่างสำหรับกรอกและลงนามด้วยมือ เว้นเลขที่ วันที่ ชื่อ และตัวเลือกไว้ พิมพ์ได้ทั้ง 12 แบบแบบละ 1 หน้า A4 ตามแนวกระดาษ โดยไม่ต้องสร้างหรือบันทึกเอกสารในระบบ

| แบบฟอร์ม | การใช้งาน / ผู้ลงนาม |
|---|---|
| FM-IT-001 | ทะเบียนคอมพิวเตอร์ เลือกดึง ATS / INNO / ทุกบริษัทได้; เจ้าหน้าที่ IT และผู้อำนวยการฝ่าย |
| FM-IT-002 | ผลตรวจโครงสร้างพื้นฐาน 12 เดือน: ปกติ / ผิดปกติ / แก้ไขแล้ว; ผู้ตรวจและผู้ทบทวน |
| FM-IT-003 | ใบแจ้งซ่อม แยกผู้ร้องขอ–หัวหน้าฝ่าย–ผู้รับแจ้ง กับผลแก้ไข–ผู้ตรวจรับ–ผู้รับรอง |
| FM-IT-004 | ประวัติบำรุงรักษา BM/PM ดึงจากหน้าอุปกรณ์ได้ ไม่เพิ่มขั้นอนุมัติ |
| FM-IT-005 | รายงานสำรองข้อมูล Server พร้อมแหล่งจัดเก็บ ขนาด เวลา ผู้จัดทำและผู้รับทราบ |
| FM-IT-006 | แผนบำรุงรักษา / สำรองข้อมูล 12 เดือน × 4 สัปดาห์ แยก P/A; ผู้จัดทำ ผู้ทบทวน ผู้อนุมัติ |
| FM-IT-007 / 007.1 | ขอซื้อครุภัณฑ์ แบบ Rev.02 และ INNO พร้อมสเปก ใบเสนอราคา ผู้ขาย ราคา/VAT และผู้รับรองจัดซื้อ |
| FM-IT-008 | คำขอเบิก–ยืมต้องให้ Admin IT Hub อนุมัติก่อน ระบบจึงเพิ่มบันทึกผู้ยืม/อุปกรณ์ แล้ว IT เติม Serial และบันทึกวันคืน ผู้คืน ผู้รับคืน และสภาพได้ |
| FM-IT-009 | ขอ E-mail ผู้ขอ หัวหน้าแผนก ผู้จัดการฝ่าย เจ้าหน้าที่ IT และ ผอ./ผจก.; ไม่เก็บรหัสผ่านบัญชีในเอกสาร |
| FM-IT-010 | IT Request ใช้แม่แบบ PDF Rev.01 เดิม รวมลายเซ็นผู้ช่วยกรรมการผู้จัดการเมื่อขอลงนามในโมดูลเอกสาร |
| FM-IT-011 | ผู้มาติดต่อภายนอก รับลิงก์ลงนามทางอีเมล พร้อมเจ้าหน้าที่ IT และผู้อนุมัติ/รับทราบ |

บันทึกฉบับร่างก่อนส่งลงนาม กรอกเฉพาะขั้นคำขอได้ก่อน แล้วบันทึกผลดำเนินการหลังลงนามคำขอครบ ขั้นรับรองจะบังคับข้อมูลที่จำเป็นและผู้ลงนามทุกตำแหน่งตามแบบฟอร์ม โดยลงนามตามลำดับ ไม่ใช้ชื่อใน Excel แทนลายเซ็นจริง

พนักงานรับลิงก์อายุ 7 วัน ใช้ token สุ่มและเก็บเฉพาะ hash เช่นเดียวกับใบคำขอเดิม เลือกใช้ลายเซ็น E-Procurement หรือวาดใหม่แล้วกดยืนยัน ผู้มาติดต่อภายนอกวาดเอง เจ้าหน้าที่ลงนามได้เฉพาะบัญชีที่เลือกไว้ด้วยลายเซ็นประจำบัญชีของตนและต้องกดยืนยันทุกครั้ง ข้อมูลที่ส่งลงนามถูกล็อก ลายเซ็นเป็นสำเนาที่ไม่เปลี่ยนตามโปรไฟล์ภายหลัง หากไม่รับรองต้องมีเหตุผล หากต้องแก้ฉบับที่ล็อกแล้วให้สร้างฉบับใหม่ ซึ่งจะขอลงนามใหม่ทุกตำแหน่ง

ฉบับพิมพ์ใช้โลโก้ ATS และ Noto Serif Thai จากเว็บเอง จัดตาราง หมวดข้อมูล และช่องลงนามตามตัวอย่าง แนวตั้ง/แนวนอนแยกตามแบบฟอร์ม ตารางยาวต่อหน้าและพิมพ์หัวตารางซ้ำ ข้อมูลครบไม่ตัดทิ้ง สถานะฉบับร่าง/รอลงนามแสดงในเอกสารก่อนรับรองครบ

จากหน้าใบงานมีปุ่ม **จัดทำเอกสาร FM-IT** สำหรับคัดลอกข้อมูลที่เกี่ยวข้องมาจัดทำฉบับใหม่ โดยไม่คัดลอกลายเซ็นหรือเปลี่ยนสถานะใบงานต้นทาง หน้าอุปกรณ์มีปุ่มจัดทำ FM-IT-004 ขั้นตอนใบคำขอเดิมยังทำงานตามเดิมแยกจากโมดูลเอกสาร

อ่านและนำเข้าข้อมูลรายงานเก่าจาก Excel เป็นฉบับร่าง (ต้องมี Python 3 และผู้ดูแลระบบ):

```bash
python3 api/bin/read-fm-workbooks.py FM-IT /private/fm-drafts.json
php api/bin/import-fm-documents.php /private/fm-drafts.json          # ตรวจอย่างเดียว
php api/bin/import-fm-documents.php /private/fm-drafts.json --apply  # เพิ่มฉบับร่าง
php api/tests/documents_workflow.php
```

JSON ที่อ่านจาก Excel มีข้อมูลภายใน ต้องเก็บนอก web/Git root สคริปต์เก็บวันที่ตามค่าต้นฉบับและเตือนค่าที่ไม่สมบูรณ์ ไม่เดาปีหรือแปลสี/เส้นในแผน P/A เป็นงานที่ทำแล้ว นำเข้าซ้ำข้าม sheet เดิมด้วย source key ไม่ทับข้อมูลที่ผู้ใช้แก้ไข ไม่เพิ่มอุปกรณ์ซ้ำ ไม่รับรองย้อนหลัง และไม่ส่งอีเมล การทดสอบใช้ temporary tables กับ SMTP จำลองเท่านั้น

### บันทึกเบิก–ยืมอุปกรณ์ FM-IT-008

ผู้ใช้ส่งคำขอที่ `/request/borrow` ระบุผู้ยืม แผนก วัตถุประสงค์ อุปกรณ์ จำนวน และช่วงเวลา คำขอจะรอ **Admin IT Hub อนุมัติ** และยังไม่เข้าบันทึก ไม่ต้องเลือกหัวหน้าฝ่ายจาก E-Procurement หรือส่งอีเมลขอลายเซ็น

ปุ่ม **+ เพิ่มรายการอุปกรณ์** รองรับ 1–50 รายการต่อคำขอ แต่ละรายการระบุประเภท Notebook/อื่นๆ ชื่ออุปกรณ์ และจำนวน 1–100 ได้แยกกัน ใช้วันเริ่มใช้ กำหนดคืน และวัตถุประสงค์ร่วมกัน Admin ตรวจรายการทั้งหมดก่อนอนุมัติครั้งเดียว ระบบสร้างบันทึก FM-IT-008 หนึ่งฉบับที่มีทุกรายการ แต่ละรายการเติม Serial และบันทึกคืนคนละวันได้ ข้อมูลรายการเดียวเดิมยังเปิดและอนุมัติได้ตามเดิม

เมนู **บันทึกเบิก–ยืมอุปกรณ์** (`/admin/borrows`) แสดงคำขอรออนุมัติแยกจากทะเบียนที่อนุมัติแล้ว กด **ตรวจสอบ / อนุมัติ** เพื่ออ่านคำขอในหน้าใบงาน แล้วเลือก **อนุมัติและเพิ่มเข้าบันทึก FM-IT-008** ระบบจะเปลี่ยนใบงานเป็นรับเรื่องแล้วและสร้างบันทึกหนึ่งฉบับใน transaction เดียว เก็บชื่อบัญชี Admin ผู้อนุมัติ เวลา และหมายเหตุ เชื่อมกลับคำขอต้นทาง การกดซ้ำคืนบันทึกเดิม ไม่สร้างซ้ำ หากไม่อนุมัติต้องกรอกเหตุผลและไม่มีบันทึกเกิดขึ้น

API ป้องกันการข้ามอนุมัติผ่านเปลี่ยนสถานะใบงาน สร้างเอกสาร008โดยตรง prefill หรือ copy ทั้งจาก UI และ URL/API เก่า ข้อมูลผู้ยืม/อุปกรณ์/จำนวน/ช่วงเวลาที่อนุมัติแล้วแก้ไม่ได้ ต้องส่งคำขอใหม่ การเติม Serial เจ้าหน้าที่จ่าย วันใช้งานจริง หมายเหตุ และข้อมูลคืนยังทำได้ พร้อมตรวจ version ป้องกันเขียนทับการแก้ไขพร้อมกัน

เมื่อคืน เปิดบันทึกเดิมแล้วกรอก **บันทึกการคืน** แยกรายการ หรือกด **รับคืนวันนี้** เพื่อเติมวันและชื่อเบื้องต้น ตรวจชื่อและกรอกสภาพอุปกรณ์ก่อนบันทึก วันที่คืนต้องไม่ก่อนวันใช้งาน คืนบางรายการก่อนได้ ทะเบียนแสดงจำนวนรายการที่ยืมอยู่/คืนแล้ว ค้นหาชื่อผู้ยืม อุปกรณ์ หรือ Serial ได้ พิมพ์ FM-IT-008 A4 แนวนอนได้ทั้งแบบมีข้อมูลและแบบเปล่า ชื่อเจ้าหน้าที่ในทะเบียนเป็นข้อมูลบันทึก ไม่มีนำภาพลายเซ็นของผู้อื่นมาใส่อัตโนมัติ

จากใบคำขอที่อนุมัติแล้ว ใช้ **เปิดบันทึก / พิมพ์ FM-IT-008** เพื่อเติมข้อมูลการจ่าย/คืนและพิมพ์แบบฟอร์ม ผู้ร้องขอติดตามผลรออนุมัติ/อนุมัติ/ไม่อนุมัติได้จากเลขที่คำขอ ทดสอบด้วย `php api/tests/borrow_records.php` (temporary tables ไม่มีอีเมลออก)

## Map NAS

เมนู **Map NAS** (`/admin/nas`) สำหรับ Admin ตั้งค่าการเชื่อมต่อ SMB หนึ่งโฟลเดอร์ วางพาธจาก Windows Explorer ในรูปแบบ `\\192.168.1.10\Documents\IT` พร้อมชื่อผู้ใช้ รหัสผ่าน และโดเมนถ้ามี รองรับชื่อโฟลเดอร์ภาษาไทยและช่องว่าง ใช้ IP ภายในเครือข่ายช่วง 10.x, 172.16–31.x หรือ 192.168.x และพอร์ต 445

**ทดสอบการเชื่อมต่อ** อ่านรายการไฟล์โดยไม่บันทึก ส่วน **บันทึกและเชื่อมต่อ** ทดสอบให้สำเร็จก่อนเก็บการตั้งค่า ถ้าทดสอบไม่ผ่านจะคงการตั้งค่าเดิมไว้ แสดงไฟล์/โฟลเดอร์ไม่เกิน 100 รายการพร้อมขนาดและเวลาแก้ไข การเชื่อมต่อใช้ SMB โดยไม่เมานต์ไดรฟ์ในระบบปฏิบัติการ งานที่เสร็จสิ้นจะส่ง PDF ผ่านคิวด้านล่างโดยใช้ปลายทางนี้

เมื่อแก้การตั้งค่า เว้นรหัสผ่านว่างเพื่อใช้ค่าเดิมได้เฉพาะเครื่อง แชร์ และบัญชีเดิม เปลี่ยนปลายทางหรือบัญชีต้องกรอกรหัสผ่านใหม่ ปุ่ม **ยกเลิกการเชื่อมต่อ** ลบการตั้งค่าและบัญชีที่เก็บไว้ ไม่แก้ไฟล์บน NAS ใช้ revision ป้องกัน Admin เขียนทับกัน

เซิร์ฟเวอร์ต้องมี PHP sodium, `proc_open`, Python 3 และแพ็กเกจตาม `deploy/nas-requirements.txt` ติดตั้งแพ็กเกจให้ตรงกับ Python ที่ PHP ใช้ ตัวอย่างเตรียมเครื่องใหม่ (ปรับ owner/group ให้ตรงกับ PHP-FPM):

```bash
sudo install -d -m 0755 /var/lib/it-hub
sudo install -d -m 2770 -o www-data -g www-data /var/lib/it-hub/nas
sudo python3 -m pip install --target /var/lib/it-hub/python -r deploy/nas-requirements.txt
php api/tests/nas_mapping.php
python3 api/tests/nas_transport.py /var/lib/it-hub/python
```

หากไม่มี pip ให้ติดตั้งแพ็กเกจ `python3-pip` ของระบบก่อน กำหนด `nas.state_dir`, `nas.python`, `nas.python_packages` ใน `api/config.php` ตามตัวอย่าง ค่า `state_dir` และ `python_packages` ต้องอยู่นอก repository, web root และ upload directory; PHP-FPM ต้องอ่านแพ็กเกจและเขียน `state_dir` ได้ ห้ามเปิด Alias ให้ directory เหล่านี้

การตั้งค่าทั้งชุดเก็บแบบเข้ารหัสด้วย sodium secretbox ใน `mapping.enc` และกุญแจสุ่มใน `secret.key` สิทธิ์ไฟล์ 0660 ภายใน directory ส่วนตัว สำรองทั้งสองไฟล์พร้อมกันโดยแยกจาก source code อย่าลบกุญแจขณะยังมีการตั้งค่าเดิม ระบบส่งรหัสผ่านให้ตัวเชื่อมต่อผ่าน stdin เท่านั้น ไม่ส่งกลับ API หรือใส่ใน command line/environment/log และไม่ตาม DFS referral หรือ symlink เพื่ออ่านไฟล์นอกโฟลเดอร์ การทดสอบใช้ข้อมูลจำลองและพื้นที่ชั่วคราว ไม่มีเปลี่ยน DB หรือเขียนไฟล์บน NAS

### ส่งเอกสารปิดงานไป NAS อัตโนมัติ

เมื่อใบงานเปลี่ยนเป็น **เสร็จสิ้น** ระบบบันทึก snapshot เอกสารลง `ticket_archives` ใน transaction เดียวกับการปิดงาน ตัวส่งเบื้องหลังสร้าง PDF จากส่วนพิมพ์ Vue เดียวกับหน้าใบงาน (FM-IT-010/007 และบันทึก FM-IT-008 ที่เชื่อมไว้; แบบอื่นใช้ฉบับพิมพ์ใบงานเดิม) พร้อมข้อมูลและลายเซ็นที่บันทึกจริง ไม่ต้องเปิดเบราว์เซอร์ผู้ใช้ ไม่มี URL สาธารณะที่เปิดเอกสารส่วนบุคคลได้

ไฟล์อยู่ในโฟลเดอร์ย่อยตามรหัสแบบฟอร์มภายใต้ Map NAS เช่น `FM-IT-008/FM-IT-008_เลขที่ใบงาน_รุ่นคิว.pdf` และ `FM-IT-010/FM-IT-010_เลขที่ใบงาน_รุ่นคิว.pdf` ระบบสร้างโฟลเดอร์ให้อัตโนมัติเมื่อมีไฟล์ประเภทนั้น ชื่อไฟล์ไม่ใส่ชื่อบุคคล หน้าใบงานแสดงพาธสัมพัทธ์นี้ด้วย ตัวส่งตรวจขนาดและ SHA-256 เขียนไฟล์ชั่วคราวในโฟลเดอร์เดียวกับไฟล์จริง ตรวจข้อมูลอ่านกลับแล้วเปลี่ยนชื่อแบบไม่เขียนทับไฟล์อื่น หาก NAS ขัดข้อง งานยังเป็นเสร็จสิ้นและคิวยังคงอยู่ ลองใหม่ทุก 5 นาทีสูงสุด 8 ครั้ง จากนั้น Admin ตรวจ Map NAS แล้วกดส่งอีกครั้งได้ เปลี่ยนปลายทาง NAS ต้องกดส่งอีกครั้งเพื่อยืนยันใช้ค่าปัจจุบัน ไม่ส่งคิวเก่าไปเครื่องใหม่โดยเงียบๆ

หลังอัปเดตจากระบบที่เคยส่งไฟล์รวมไว้ที่โฟลเดอร์หลัก ให้รัน `php api/bin/archive-folders.php` เพื่อย้ายเฉพาะไฟล์ที่มีสถานะส่งสำเร็จและตรง mapping revision ปัจจุบัน ใช้ worker lock ร่วมกับตัวส่ง ตรวจขนาด/SHA-256 ก่อน rename เข้าโฟลเดอร์แบบฟอร์มโดยไม่แก้เนื้อหาไฟล์ หากปลายทางมีไฟล์อยู่แล้วจะตรวจทั้งสองไฟล์ก่อนลบเฉพาะสำเนาซ้ำที่โฟลเดอร์หลัก ข้อมูลไม่ตรงจะไม่ย้าย/ไม่ทับ ไม่ย้ายไฟล์อื่นที่ไม่ได้อยู่ในทะเบียน archive และรันซ้ำหรือทำต่อหลังขัดจังหวะได้ คงชื่อไฟล์/รุ่นคิว/วันส่งเดิมไว้

หน้าใบงานแสดงรอส่ง/กำลังส่ง/สำเร็จ/ผิดพลาด ชื่อไฟล์และเวลาส่ง รายการใบงานแสดงสถานะ NAS ใต้สถานะงาน หากเพิ่มลายเซ็นจัดซื้อหลังปิดงาน แก้ผลดำเนินการ หรือบันทึกคืนอุปกรณ์ของงานที่ปิดแล้ว ระบบเข้าคิวฉบับใหม่และเก็บฉบับเก่าไว้ คิวเก่าที่ยังไม่ส่งจะข้ามเมื่อมีฉบับใหม่กว่าหรือเปิดงานใหม่ ไฟล์ PDF ที่ส่งแล้วและ cache ส่วนตัวไม่ลบอัตโนมัติ

ติดตั้ง migration10 และ Node.js/Playwright/Chromium พร้อมไลบรารีระบบที่ Chromium ต้องใช้ runtime อยู่ภายนอก web root (`deploy/archive-runtime.package.json` ระบุเวอร์ชันที่ใช้ทดสอบ) ตั้งค่า `archive` ตาม `api/config.example.php` หรือใช้ directory `archive` ข้าง `nas.state_dir` ค่าเริ่มต้น ภายในมี `node_modules/playwright` และ Chromium ที่ `chromium/chrome` ให้บัญชีตัวส่งอ่าน/เขียนได้ ส่วน PDF/cache/worker log ห้ามวางใน public directory `web/dist/archive-print.html` มีเฉพาะหน้าพิมพ์ว่าง ใช้ payload ที่ process ป้อนใน memory และ renderer บล็อกการเชื่อมต่อภายนอกทั้งหมด

ตั้ง cron ในนามบัญชีที่อ่าน config และ private NAS state ได้ (คงงาน cron เดิมไว้):

```cron
* * * * * /usr/bin/php /var/www/IT-Hub/api/bin/archive-worker.php >> /var/www/it-hub-private/archive/worker.log 2>&1
```

ตัวส่งมี file lock ป้องกันรันซ้อนและกู้คิวที่ถูกขัดจังหวะ สามารถส่งงานที่ปิดอยู่เดิมครั้งแรกด้วย `php api/bin/archive-worker.php --backfill` (จะอัปโหลดไฟล์จริง) ทดสอบแบบไม่ส่ง NAS ด้วย `php api/tests/archives.php`, `python3 -B api/tests/nas_upload.py /path/to/python-packages` และ `php api/tests/archive_render.php /private/output-dir` (ทดสอบ renderer ต้อง build frontend และติดตั้ง runtime ก่อน) สำรอง DB ตารางคิวพร้อม private PDF cache และ encrypted NAS state โดยเก็บสิทธิ์ส่วนตัวไว้
