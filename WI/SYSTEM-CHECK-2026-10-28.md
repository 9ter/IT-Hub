# สถานะที่ตรวจพบและขอบเขตที่ยังไม่ยืนยัน

| รายการ | สิ่งที่ยืนยันได้ในรอบนี้ |
| --- | --- |
| ทะเบียนอุปกรณ์ | ฐานข้อมูลมี 149 รายการ |
| ใบงานคำขอ | ฐานข้อมูลมี 10 รายการ |
| archive | ฐานข้อมูลมีสถานะ sent 5 รายการ เป็นหลักฐานสถานะที่ระบบเก็บไว้ ไม่ใช่การอ่านไฟล์ NAS ซ้ำในรอบนี้ |
| Map NAS | มีค่าตั้งแล้ว และ runtime พร้อม; ไม่แสดงปลายทาง/บัญชีจริงในเอกสาร |
| ตัวส่งเบื้องหลัง | cron service active และมีรายการเรียก archive-worker ของ IT Hub 1 รายการ |
| สร้าง PDF | archive_render.php สร้างได้ครบ repair/service/purchase/email/borrow จากข้อมูลทดสอบในตารางชั่วคราว ไม่อัปโหลด |
| ภาพประกอบ | จับหน้าจอ frontend ที่ให้บริการจริง โดย API ของภาพประกอบใช้ข้อมูลสมมติ ไม่มีข้อมูลคำขอจริงหรือลายเซ็นของบุคคลจริง |

รายการที่ต้องยืนยันหน้างานก่อนสรุปการยอมรับระบบครบวงจร:

1. ผู้อนุมัติได้รับอีเมลจริง เปิดลิงก์และลงนามจากอุปกรณ์ของตน การทดสอบรอบนี้ไม่ส่งอีเมลจริง
2. พิมพ์สติกเกอร์กับเครื่องจริง ตั้งกระดาษ 50 × 40 มม. และทดสอบสแกน QR บน Wi-Fi โรงงาน
3. ทดสอบการใช้งานจากเครือข่ายภายนอกที่ต้องการใช้งานจริง ผล HTTPS ในรายงานมาจากเครื่องเซิร์ฟเวอร์/เบราว์เซอร์อัตโนมัติบนเครื่องนี้
4. การเปิด/แก้ไขใบงานจริงและใช้งาน Admin ด้วยบัญชีผู้ปฏิบัติงานจริง รอบนี้ทดสอบพฤติกรรมเขียนในตารางชั่วคราวและ UI fixtures เพื่อไม่เปลี่ยนงานจริง
5. การส่ง PDF ฉบับใหม่และเปิดไฟล์ปลายทาง NAS จริง รอบนี้ตรวจสถานะที่มีอยู่และทดสอบระบบส่งด้วย transport จำลอง ผล sent เดิมไม่ยืนยันสภาพเครือข่าย/สิทธิ์เขียน ณ เวลาในอนาคต

> ไม่ใช่การตรวจประเมินความปลอดภัยหรือโหลดเทสต์ทั้งระบบ ผลนี้ครอบคลุมกรณีที่ระบุและข้อมูลตัวอย่างที่ใช้ตรวจเท่านั้น ไม่ได้เปลี่ยนสิทธิ์ บัญชี การตั้งค่า NAS หรือข้อมูลใบงานจริง

# หลักฐานและการตรวจรับเอกสาร

หลักฐานที่เผยแพร่ร่วมกับคู่มือ: validation/test-results.json, validation/browser-results.json, validation/health.json, validation/lint.json และ validation/artifact-checks.json เป็นข้อมูลสรุป ไม่มีรหัสผ่าน token ลายเซ็นจริง หรือข้อมูลใบงานรายบุคคล

หลักฐานดิบและ PDF ทดสอบเก็บในพื้นที่สำรองส่วนตัวของผู้ดูแลเซิร์ฟเวอร์ ส่วนคู่มือ ภาพ และ source Markdown อยู่ใน docs/wi

การตรวจเอกสารก่อนส่งมอบ:

1. ตรวจว่า Markdown ทุกภาพอ้างอิงไฟล์ที่มีอยู่ และ HTML ฝังภาพ/ฟอนต์เพื่อเปิดแบบออฟไลน์ได้
2. สร้าง PDF จาก HTML แล้วตรวจจำนวนหน้า ขนาด A4 และข้อความค้นหาได้
3. ตรวจภาพหน้ากระดาษตัวอย่าง ปก สารบัญ ขั้นอนุมัติ บันทึกคืน NAS และหน้าสุดท้าย ไม่ให้รูป/ข้อความถูกตัดข้ามหน้า
4. บันทึก SHA-256 ของไฟล์ส่งมอบและภาพใน validation/artifact-checks.json
5. เก็บการเปลี่ยนแปลงเดิมใน working tree ไม่ commit/push หรือ deploy โดยอัตโนมัติ

ข้อค้นพบด้านเอกสาร: หัวข้อส่งต่องานเก่าตอนต้น MEMORY.md ยังระบุว่า NAS อ่านอย่างเดียว ทั้งที่บันทึกใหม่และโค้ดรองรับส่ง PDF/แยกโฟลเดอร์แล้ว จึงจัดทำ WI อิงโค้ดปัจจุบัน ผลทดสอบ และบันทึกท้ายไฟล์ พร้อมอัปเดตสถานะส่งต่อให้ตรงกัน
